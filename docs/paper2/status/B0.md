### Account labels (`derive_surface/p2ids.py`)

- `p2ids.label(subaccount) -> str`: `M1` to `M10` for the ten subaccounts with the most maker fills in
  `data/p1/derived/markouts.parquet` (ties broken by the smaller ID, the same rule as
  `books.top_maker_subaccounts`), otherwise `X` plus the first 10 hex digits of `HMAC-SHA256(salt, str(id))`.
  In addition `p2ids.labels(iterable) -> list[str]`, `p2ids.top_makers() -> list[int]`, `p2ids.Labeler(ranking, salt)`
  for tests and `p2ids.reset()`.
- Salt: `data/p2/secret_salt.txt`, 32 random bytes in hex (64 characters), created once on 25 September 2026,
  permissions 0600, ignored by git. `create_salt` creates the file only if it is missing (`O_EXCL`) and never
  overwrites it. `label` does not create a salt: if the salt is missing, it stops with `FileNotFoundError` instead
  of silently returning different X labels.
- Ranking: read from the markouts (only the column `maker_sub`, 603,940 fills, 0.05 s). If
  `data/p2/books/top_makers.json` (A5) also exists and differs, `top_makers()` stops with `RuntimeError`, because
  the books would then have been loaded for other accounts. For the final data run, check `p2 books top` first.
  Today both agree.
- Assignment (maker fills from `data/p2/books/top_makers.json`): M1 101,791, M2 39,910, M3 32,567, M4 31,795,
  M5 30,109, M6 27,227, M7 22,173, M8 21,707, M9 19,133, M10 16,618. The four PM2 accounts of the H2 population are
  M3 (PM2:HYPE), M5, M8 and M10 (PM2:ETH).
- CLI: `python3 -m derive_surface p2 ids salt` (creates the salt if it is missing) and
  `python3 -m derive_surface p2 ids label <id> ...` (terminal only).

### CLI (`derive_surface/p2cli.py`, `derive_surface/__main__.py`)

`python3 -m derive_surface p2 <command> ...` passes the remaining arguments unchanged to `main(argv)` of the
module, `--help` included. The return value of `main` becomes the exit code (`None` counts as 0).

| Command | Module | Task |
|---|---|---|
| `feeds` | `p2feeds` | A1 |
| `params` | `p2params` | A2 |
| `books` | `books` | A5, B3 |
| `validate` | `p2validate` | B1 |
| `capital` | `capital` | B2 |
| `events` | `p2events` | B4 |
| `surface` | `p2surface` | B5 |
| `infer` | `inference_p2` | C1 |
| `figures` | `figures_p2` | D1 |
| `ids` | `p2ids` | B0 |

If a module is missing, the call ends with exit 1 and the message `p2 <command>: module derive_surface.<module> is
not implemented yet (task <Task> of docs/superpowers/plans/2026-09-24-p2-master-plan.md)`. If instead a dependency
inside an existing module is missing, the original `ModuleNotFoundError` stays visible. A module without `main`
gives a message of its own. Memory-intensive runs still go through
`python3 scripts/p2_heavy.py --wait-max 500 -- python3 -m derive_surface p2 ...`.

### Final data run of the parameters (`derive_surface/p2params.py`)

Finding from A2: `Loader.__init__` took over `--to-block` only as long as `data/p2/params/meta.json` was missing,
and the log caches `logs_*.json` had no record of the block they reach up to. A run after 1 October 2026 would
have kept the old end block 45,130,786.

- `--to-block N` now always applies and is stored in `meta.json` (the old value under `previous_to_blocks`).
  Without `--to-block` the stored end block applies, and without `meta.json` the chain head, as before.
- Every log cache stores its filter (addresses, topics, start block) and the end block it covers. It is reloaded
  when the end block goes beyond the covered one or the filter changes (for example new override libs); a smaller
  end block truncates. The caches of the first run (plain lists) are tagged at start with the old end block from
  `meta.json` before `meta.json` receives the new end block. An interrupted run therefore never mistakes an old
  cache for the new range. The snapshot caches are exact to the block and stay valid.
- Checked offline on a copy of the real A2 caches with an RPC that refuses every request: 565 of 565 events equal
  to `events_decoded.json`, no request; a new end block requests `eth_getLogs`. The caches under
  `data/p2/params/` themselves are unchanged; the conversion happens on the next run.
- Final data run: `python3 -m derive_surface p2 params load --to-block N --max-seconds 520`, repeated (without or
  with the same `--to-block`) until `DONE`. N is for example `p2chain.block_at_ts(ts)` for the end of the sample
  plus a buffer.

### Re-pseudonymisation

- `results/p2/params/{BTC,ETH,HYPE}_pm2_overrides.json` (15, 16 and 10 rows) now carry `p2ids` labels instead of
  `sha256(str(id))[:10]`, rewritten without RPC from `data/p2/params/{CCY}_pm2_overrides_raw.json` with
  `python3 -m derive_surface p2 params relabel`. Four rows belong to M accounts (ETH: M5, M8, M10; HYPE: M3); the
  other 37 accounts are X labels. Before writing, `relabel_overrides` checks per row the lib, block and time and
  that the old hash belongs to the raw ID. Cross-check: with the new files `account_lib` returns in 759 of 759
  queries (every account at every assignment time, one second before it and in 2033) the same lib as with the old
  ones.
- `p2params.overrides_from_events`, `overrides_from_raw`, `account_lib` and `pm2_params_for_account` take an
  optional `label=`; by default `p2ids.label` applies. `account_hash` (unsalted) is removed.
- `docs/paper2/DATA_STATUS.md`: the 41 occurrences of the unsalted hashes of the ten accounts replaced by M1 to
  M10, and the three sentences that described the old pseudonym adjusted; nothing else changed.
  `docs/paper2/get_margin_semantics.md`: the raw account ID of an override account replaced by its X label.
- Check: `results/`, `docs/paper2/` and `paper2/` contain none of the 47 raw IDs (ten accounts plus override
  accounts) and no unsalted hash. From now on the test `test_no_unsalted_account_hashes_in_results_or_docs` guards
